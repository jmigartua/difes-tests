Formulas, sessions, views, libraries

The three levels of the program: the math language for physics, the session graph for an analysis, the view specification for graphics; and the libraries where formulas and views are kept.

The math language

A formula is either a bare expression over named inputs, or a function definition in the form FOCUS’s formula editor uses:

name(x, a, b) = expression

The first argument is by convention the variable (the wavenumber); the rest are parameters. Grammar, in order of increasing precedence: comparisons (==, <, >, <=, >=, giving 1 or 0 as in FOCUS), + -, * /, unary -, power ^ (or **, right-associative), then numbers, names, calls and parentheses. Numbers are 1, 2.5, 1e-3; the imaginary unit is i (also I or 1j); constants PI, E, LN2, LN10; RND is a random number in [0, 1).

Functions, FOCUS names first, Python-style aliases after them, looked up case-insensitively:

group functions note
complex Real, Imag, Abs, Arg, Norm (\(|z|^2\)), Conjg/Conj
algebraic Sqr (\(z^2\)), Sqrt/Root, Exp, Ln, Log (base 10, as FOCUS), Log10, Pow the principal square root
trigonometric, hyperbolic Cos … Atan, Cosh … Atanh, and the co-functions
logic If(cond, a, b), Heaviside, Clip(z, lo, hi), Min, Max conditions are 1/0 arrays
special dawson Dawson's integral, for causal Gaussians
FOCUS profiles phonon_4p(x, wTO, gTO, wLO, gLO), phonon_3p(x, dEps, w0, g), drude(x, wp, g) FOCUS's argument order
reductions sum(...), product(...) variadic

Everything is evaluated with numpy on arrays; there is no eval and no access to Python names, so a formula from a library or a FOCUS file is safe to run.

difes eval "g(x, a) = a*Exp(-x/1000)" --x 0 2000 5 --set a=2
difes eval "Norm((Sqrt(4 + 0.5*i) - 1)/(Sqrt(4 + 0.5*i) + 1))"
difes eval "R_fresnel(x, 1, Sqrt(4 + 0.5*i))" --x 100 1000 3

--x LO HI N sets the grid, --set NAME=VALUE a parameter; a formula may call any function of the libraries (the third line uses the built-in R_fresnel). A complex result prints its real and imaginary parts.

A formula becomes a model term with {"kind": "expr", "formula": "...", ...parameters} in a model file, and is then fitted like a built-in term. Causality is the author’s responsibility; kk.causality_error in the Python interface checks it numerically.

Sessions

A session is a graph of named nodes; each node has a kind, a specification, and outputs that other nodes reference as @node (the main output) or @node:output. Evaluation is lazy and cached: a node is recomputed only when its own specification or one of its inputs changed. The file is JSON.

kind specification outputs
data path, kind, unit, columns, range, temperature, name out: the spectrum
model model: a model object as in a model file out: the model; term0, term1, …: each term alone
sample model=@m, substrate=@m2 (optional), thickness, coherent out: the sample record
quantity sample=@s, kind, grid=[lo, hi, n] or x=@node (its grid), term=i (that term's \(\chi\) only) out: the spectrum
expr formula, inputs={name: @ref or number}, kind, x (which input gives the grid) out: a spectrum, or a scalar
transform op, input=@ref, and per operation: crop (lo, hi), interpolate (grid), derivative, scale (factor), offset (value), to-R, to-E, kk-phase (form), kk-chi1, mskk (anchors), cfrc (model, anchors, positive, poles or knots) out; params and correction for cfrc
fit terms=[{data: @d, sample: @s, weight, sigma}], options model (fitted), result (numbers), report (text), curve0, curve1, …
view view: a view specification data: the curve arrays

In an expr node the inputs that are spectra are interpolated onto one grid (the first input’s, or the one named by x) and their y arrays are bound to the input names; x is the grid itself. So "formula": "data - R_model" with inputs data and R_model is a residual, and "formula": "Gauss(x, 0.5, 500, 100)" is a synthetic curve on the grid of any spectrum input.

difes session example > s.json      # a complete small session to start from
difes run s.json --out out           # evaluate every node, write every output
difes run s.json --only fit fig      # only these nodes (and what they need)
difes view s.json fig -o fig.png     # render one view

run writes spectra as text files, models as JSON, reports as text and views as PNG, named node.output.ext in the output directory, and prints a line per output.

A session file keeps a path to its data relative to its own directory, so a folder with the session, the data and the output directory is a self-contained, reproducible analysis. The Python interface (Session.add, set, set_parameter, get) builds and edits sessions programmatically; a shell edits the same graph interactively.

Views

A view is a declarative record; it holds no data, only references to session outputs, so the same view is rendered by the core for export and by a shell on screen from the same curve arrays.

{"title": "truncated Kramers-Kronig phase",
 "x": {"label": "wavenumber (cm^-1)", "lim": [100, 3000]},
 "y": {"label": "phase", "lim": [0, 3.2]},
 "curves": [{"source": "@theta_true", "label": "exact"},
            {"source": "@theta", "label": "KK on 100-3000", "style": {"ls": "--"}},
            {"source": "@error", "label": "error", "hidden": true}],
 "size": [8, 4.5], "legend": true}

part selects real (default), imag, both, abs or re-im (real versus imaginary) for complex expression outputs; style passes matplotlib line options; hidden keeps a curve in the data without drawing it. Log axes: "log": true in x or y.

Libraries

Formulas, terms and views live in three scopes, looked up in this order:

  • project: a JSON file next to the session, given with --project; the working notes of one analysis;
  • app: the group’s shared library, one JSON file at ~/.config/difes/library.json (or DIFES_APP_LIBRARY), later a package in the Guix channel;
  • built-in: shipped with difes; FOCUS’s formula-editor examples (Gauss, Lor, R_fresnel, Planck_WN) and worked-example terms (lorentz_term, drude_term), read-only.

Every entry carries provenance: author, date, source, note. Promotion copies an entry to a wider scope and records why; the project entry keeps shadowing the app one until it is removed.

difes library list
difes library add bump function "bump(x, xc, w) = Exp(-Sqr((x - xc)/w))" --project lib.json --by josu --source "paper X"
difes library promote bump --to app --reason "validated on quartz" --by josu --project lib.json

A name found in the libraries is callable from any formula: in eval, in an expr node, in an expression term of a model. A definition that does not parse is rejected at add.

    What this is

    The test ledger of difes, a program for dielectric-function models, reflectivity, emissivity, Kramers–Kronig and fitting of infrared spectra, built as a personal project to give the group an open and documented counterpart of FOCUS. Every check the program has passed through is listed here with its grade, its data and its result, next to the validation pages the checks come from and the complete manual: how the app looks and works, and the physics it implements, equation by equation.
